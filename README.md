# athletics-form-analysis

陸上競技向けAIフォーム解析プラットフォーム（要件定義 REQ-ATH-001 v0.2.0）の**時間軸の中核**です。
要件書 §19「最初に作る縦切り」のうち、計測の正しさを決める部分を先に作りました。

- 元動画のPTS / time_base から原本フレーム索引を作る（固定FPSで換算しない。VFR・重複PTS・欠落・順序逆転を検出）
- 撮影時間軸の確度（`verified` / `container_only` / `declared` / `slowmo_suspected` / `unknown`）を判定し、スロー書き出しでは秒単位の指標を出さない
- 接地・離地を「観測フレームで挟んだ時刻区間」として持ち、接地時間・ピッチは区間から求めた範囲つきで出す。表示桁は区間幅に合わせる
- 指標ごとの品質ゲート（角度は視点・点の可視性、時間指標は時間軸・不確実性）。判定不可には必ず理由を付ける
- 全原本フレーム解析と完全性の記録。間引きプレビューは正式な値（`valid`）にしない
- 手動訂正は自動検出を残した別レイヤーで、依存指標を再計算する
- 表示用プロキシと原本の対応（複製・欠落・補間フレームの検出）
- 原本フレーム単位のプレイヤー（0.1/0.25/0.5/1.0倍、コマ送り、イベント前後ループ）。再生倍率は解析値を変えない

## まだ作っていないもの

認証・共有・API/DB・アップロード、**実際の姿勢推定モデル**（MMPose等はライセンス確認 DEC-002/NFR-SEC-010 の後。現在は推定済みJSONを読む `FixturePoseAdapter` のみ）、動画からの実フレーム画像の表示、動画内/動画間比較、改善提案、短距離以外の種目。
同梱のデモは**合成データ**で、実在の選手データではありません。品質ゲートの閾値（接地時間の不確実性25%、ピッチ10%、観測の途切れ0.06秒、短距離の妥当範囲＝ピッチ3.0歩/秒以上・接地時間0.25秒以下）は暫定値で、実測ベンチマーク（DEC-016）で決め直す前提です。

### 分かっている限界

- イベントの時刻区間は「どのフレームの間で状態が変わったか」だけから作っています。姿勢推定の座標誤差や、接地判定の閾値（`contact_band_px`）による早まり・遅れは区間に含まれていません。合成データの足は地面から離れた位置で切り替わるため、この誤差はテストでも試せていません（G-Q3 の実測で評価が必要）。
- 原本自体がエンコーダで固定FPSに変換されていて、複製フレームに別のPTSが付いている場合は検出できません。区間の下限が真値より後になる可能性があります。
- 時間軸の処理は、FFmpeg 9.0.1 で作った試験動画（240fps、Bフレーム、可変FPS、欠落、8倍スロー書き出し、先頭カット、パケット破損）の実際の ffprobe 出力で確認済みです（`tests/fixtures/ffprobe/`）。ただし動画の中身はテストパターンで、**実際のスマホ撮影の動画や、人物の写った動画ではまだ確認していません**。端末ごとのメタデータ（iPhone のスローモーションなど）も未確認です。
- プレイヤーは骨格だけを描き、映像フレームは表示しません。「映像と骨格が同じフレームか」（AC-011 の一部）は、映像表示を作るときに検証が必要です。
- スロー書き出しの検出は、撮影FPSメタデータ（`com.android.capture.fps`）と、動きの速さが種目として自然かどうかで行っています。メタデータがなく、動きの速さがもっともらしい範囲に収まるスロー（1.5倍程度、または接地1回分しかない2倍スロー）は見分けられず、推定値として出ます。
- フレームの欠落は「近くの最短間隔の1.5倍を超え、同じ長さの間隔が（より短い間隔を挟まずに）3つ以上続いていないもの」として検出します。FPSが上がる切り替えも下がる切り替えも欠落にはしません。次の2つは原理的にFPSの切り替えと区別できず、「欠落」とは表示されません（時刻は実際のPTSで計算するので値は作られません）。実際の試験動画で、この振る舞いを固定しています（`run4_drops240`、`slowdown_drop`）。
  - 同じ長さの欠落が3回以上続く（例: 240fpsで3枚に1枚だけ記録される状態が続く）
  - FPSが下がる切り替えの直前の1枚の欠落（欠落の間隔が、新しいFPSの間隔と同じになる）
- 可変FPSの判定は、間隔のばらつきが2%を超えるかどうかです（time_base の丸め±1tickは無視）。実際のスマホのタイミングの揺れでは可変FPSと表示される可能性があります（表示のみで、計測には影響しません）。
- 観測の途切れ（0.06秒）は秒数で固定しています。15fps程度の素材や、間引きの大きいプレビューでは、すべてのフレーム間が途切れになり、時間指標はすべて判定不可になります（安全側の動作）。

## 使い方

必要なもの: Python 3.11以上（標準ライブラリのみ）、Node.js 18以上（テストのみ）、実動画を扱うときは FFmpeg（ffprobe）。

```bash
python -m athform demo --out web/demo
```

```bash
python -m http.server 8765 --bind 127.0.0.1 --directory web
```

ブラウザで http://127.0.0.1:8765 を開きます。←/→で1フレーム送り、Spaceで再生・停止。

実動画の場合（姿勢推定結果のJSONは別途用意）:

```bash
python -m athform probe input.mp4 --out probe.json
```

```bash
python -m athform analyze --probe probe.json --pose pose.json --video input.mp4 --ground-y 900 --view side --direction left_to_right --out web/snapshot.json
```

`--capture-fps`（申告の撮影FPS）や `--slowmo`（スロー書き出しの申告）を渡せます。申告は精度の証明には使われません。

## テスト

```bash
python -m unittest discover -s tests -t .
```

FFmpeg がある環境では、試験動画を作り直して、実際の ffprobe 出力が保存済みフィクスチャと一致するかも確かめられます（動画は `.cache/videos/` に作られ、コミットされません）。

```bash
python tools/make_test_videos.py --check
```

FFmpeg の場所は、環境変数 `ATHFORM_FFPROBE` / `ATHFORM_FFMPEG` → PATH → winget の既定のインストール先の順に探します。

```bash
node --test web/tests/player-core.test.js web/tests/static.test.js
```
