# athletics-form-analysis

陸上競技のフォームを、練習動画から解析するローカルアプリです（要件定義 REQ-ATH-001 v0.2.0）。
自分のPCで起動し、ブラウザで使います。動画はPCの外に出ません。

- 動画を追加すると、全ての原本フレームで姿勢推定（RTMPose）を行い、接地・離地・接地時間・ピッチ・接地時の膝角度・体幹前傾を計算します
- 実際の映像に骨格と地面の線を重ねて、1フレームずつ・0.1〜1.0倍で確かめられます（再生倍率は解析値を変えません）
- 自動で検出した接地・離地は、表示中のフレームへ移す・追加・削除で訂正できます。自動検出の結果は残り、依存する指標だけ計算し直します
- 練習日・種目・タグで履歴を検索でき、2本の動画（または同じ動画の2区間）を比べられます。差の量と不確実性だけを示し、良し悪しは判定しません
- 要件書の全種目を選べます。種目ごとに、指標を「対応 / 試験的 / 手動確認が前提 / 未対応」で出し分けます（下の表）
- 精度を保証できないときは数値を出さず、理由を表示します（撮影時間軸が不明なスロー動画、遮蔽、時間分解能の不足など）

## 起動

必要なもの: Windows / macOS / Linux、Python 3.11 以上、FFmpeg（ffprobe を含む）。

```bash
python -m venv .venv
```

```bash
.venv/Scripts/python -m pip install rtmlib onnxruntime
```

（macOS / Linux では `.venv/bin/python`）

```bash
.venv/Scripts/python -m athform.server
```

ブラウザで http://127.0.0.1:8766/ を開きます。データ（元動画・フレーム画像・解析結果）はホームフォルダの `.athform/data` に保存されます（プロジェクトの外。`--data` または環境変数 `ATHFORM_DATA` で変えられます）。
初回の解析で、姿勢推定モデルの重み（約750MB、OpenMMLab 配布）が `~/.cache/rtmlib` にダウンロードされます。

### 使い方

1. 「動画を追加」で動画と種目・撮影角度・進行方向を選ぶ（側面から、カメラを固定して撮った動画が最もよく解析できます）
2. 解析は精度優先（YOLOX-x + RTMPose-x、CPUで1フレーム約0.6〜1秒）で、画面を閉じても続きます。「軽量モデルで試す」はプレビュー扱いで、正式な値（有効）は出ません
3. 地面の線がずれているときは「映像をクリックして指定」で地面の高さを指定すると、推論なしで計算し直します
4. 接地・離地の誤りは、そのフレームを表示して「表示中のフレームへ移す」（理由の入力が必要）
5. みんなで走っている動画で、解析する人が違うときは「人を選ぶ」を押し、映像の中の人をクリックします。そのコマから前後に追い直して計算し直します（推論はやり直さないので数秒で終わります）。この機能のために、解析では写っている全員の点を保存しています（`people.json`）。以前の版のアプリで解析した動画は「姿勢推定からやり直す」の後に選べます

## 種目と指標の公開状態

| 区分 | 種目 | 接地時間・ピッチ | 接地時の膝角度・体幹前傾 | 出していない指標 |
|---|---|---|---|---|
| 短距離 | 100m / 200m / 400m | 対応 | 対応 | ストライド長・走速度（距離校正が未実装） |
| 中長距離 | 800m〜マラソン | 試験的 | 試験的 | ペース区間（ラップ・GPS 連携が未実装） |
| ハードル・障害 | 100/110mH・400mH・3000m障害 | 試験的 | 試験的 | ハードル越え・抜き脚（障害物の検出が未実装） |
| 跳躍 | 走幅跳・三段跳・走高跳・棒高跳 | 試験的（助走） | 試験的 | 跳躍角度・踏切板・バー（校正・用具検出が未実装） |
| 投擲 | やり・砲丸・円盤・ハンマー | 出さない | 手動確認が前提 | リリース角度・速度（用具検出が未実装） |
| 競歩 | 競歩 | 試験的 | 試験的 | 規則の適法性（判定しない） |
| リレー | 4×100m・4×400m | 試験的 | 試験的 | バトンの受け渡し（複数人の追跡が未実装） |

混成競技は、構成する種目を選んで解析します。「試験的」は最高でも「推定」、「手動確認が前提」は最高でも「要確認」で表示されます。
評価ルールが専門家に承認されていないため、改善提案は表示しません（要件書 FR-FB-001, §8.3）。

## 姿勢推定モデルとライセンス

- 使っているモデル: rtmlib（Apache 2.0）経由の RTMPose（Halpe26 の点、body7 で学習）と YOLOX（人物検出）。どちらも OpenMMLab の配布物
- ライブラリのコードは無料・商用可ですが、**重みの学習データ（body7: COCO, AI Challenger, MPII, CrowdPose, Halpe など）には研究・非商用に限定されたものが含まれます**。このアプリは個人での利用を前提にしています。販売・サービス提供の前には、各データセットの利用条件を確認してください（法的な助言ではありません）
- 解析結果には、使ったモデルの重みのファイル名・設定が記録されます（FR-POSE-006）

## 分かっている限界

- **人物の写った実際の動画での精度は、まだ十分に確かめていません。** 動作確認は、公開されている大会映像1本（下記）と、FFmpeg で作った試験動画・合成データで行っています。接地時間などの精度（誤差何ms以内か）は、接地センサーなどの正解データとの比較（要件書 G-Q3, DEC-016）が必要です
- 地面の線は「足が最も下に来る位置」から推定します。自動推定の地面では、指標は最高でも「推定」です。接地とみなせる点が少ない・傾きが大きすぎる・人物が小さい（体の高さ120px未満）・前半と後半で地面の高さが違う（カメラが動いている）ときは「要確認」になります。地面を画面で指定すると、確かな値（有効）を出せます。カメラが選手を追って動く映像では、地面の線は1本では表せません
- 解析対象は1人です。最初に最も大きく映った人を選び、以降は「最後に見た位置から、その間に動ける距離（1秒あたり体の大きさの8倍、0.15〜0.6倍）以内」で大きさも近い人を追います。近くに2人以上いるフレームや見失ったフレームは数値に使いません。1フレームでも見失った後に追跡を戻した所では、別人に替わった可能性があるので計算を区切ります（そのぶん、隠れやすい映像では値が出にくくなります）。見た目（服の色など）での見分けはしていないので、隣のレーンの選手が同じ位置・大きさで重なると見分けられません（重なった1フレームで本人が検出されず、隣の選手だけが同じ位置に検出されると、印なしで乗り移ることがあります）
- イベントの時刻区間は「どのフレームの間で状態が変わったか」だけから作っています。姿勢推定の座標誤差や、接地判定の幅（`contact_band_px`）による早まり・遅れは区間に含まれていません
- 原本自体がエンコーダで固定FPSに変換されていて、複製フレームに別のPTSが付いている場合は検出できません
- スロー書き出しの検出は、撮影FPSメタデータ（`com.android.capture.fps`）と、動きの速さが種目として自然かどうかで行っています。メタデータがなく、動きの速さがもっともらしい範囲に収まるスロー（1.5倍程度、または接地1回分しかない2倍スロー）は見分けられず、推定値として出ます。iPhone のスローモーションのメタデータは未確認です
- フレームの欠落は「近くの最短間隔の1.5倍を超え、同じ長さの間隔が（より短い間隔を挟まずに）3つ以上続いていないもの」として検出します。次の2つは原理的にFPSの切り替えと区別できず、「欠落」とは表示されません（時刻は実際のPTSで計算するので値は作られません。`run4_drops240`、`slowdown_drop` で振る舞いを固定）
  - 同じ長さの欠落が3回以上続く。2回続くまでは検出できます
  - FPSが下がる切り替えの直前の1枚の欠落
- FPSが1フレームごとに約11%を超えて少しずつ変わっていくと、その途中が「欠落」と表示されることがあります（該当するイベントが要確認になるだけです）
- 可変FPSの判定は、間隔のばらつきが2%を超えるかどうかです（表示のみで、計測には影響しません）
- 観測の途切れ（0.06秒）は秒数で固定しています。25〜30fps の動画では、1フレーム足が見えないだけで接地または滞空が丸ごと隠れうるため区切りになり、ピッチなどが出にくくなります。15fps程度の素材では時間指標はすべて判定不可になります（安全側の動作）
- 姿勢推定は CPU で動きます（GPU 版の onnxruntime は未対応）。精度優先モードは 1分の 30fps 動画で 20〜30分ほどかかります
- 品質ゲートの閾値（接地時間の不確実性25%、ピッチ10%、観測の途切れ0.06秒、種目ごとの妥当範囲）は暫定値です
- ログイン・コーチとの共有・複数人での利用は、この版にはありません（ローカル1人用）
- 取り消しを頼んでも終わらない解析は2分で「失敗」として閉じますが、裏で処理が続いていることがあります。そのとき削除すると「一部のファイルを削除できなかった」になることがあり、残ったファイルは次の起動時に片付けます
- 以前の版のアプリで作った解析結果は「版 1（旧形式）」として表示されます。指標の状態は当時の判定のままなので、「保存して再計算」または「姿勢推定からやり直す」を実行してください

## テスト

```bash
python -m unittest discover -s tests -t .
```

```bash
node --test web/tests/player-core.test.js web/tests/static.test.js
```

FFmpeg がある環境では、試験動画を作り直して、実際の ffprobe 出力が保存済みフィクスチャと一致するかも確かめられます（動画は `.cache/videos/` に作られ、コミットされません）。

```bash
python tools/make_test_videos.py --check
```
