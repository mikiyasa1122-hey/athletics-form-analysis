### 仮定
- 範囲: 認証・共有・API/DB・アップロード・比較・改善提案は今回作らない（F2以降）。
- 姿勢推定モデルは同梱しない。MMPose等はライセンス確認（DEC-002, NFR-SEC-010）が前提のため、推定済みJSONを読むアダプタで代える。
- FFmpegはこのPCに入っていない。ffprobeの呼び出しは偽ランナーで引数と解析だけを検証。実動画でのPTS抽出は未検証。
- 接地の検出は「画像上の地面の高さ（ground_y）を撮影条件として与える」簡易方式。実映像での精度は未検証（G-Q3はF1で）。
- 撮影メタデータがない通常動画は `container_only`（PTSを実時間とみなす）とし、時間指標は最高でも `estimated`。`valid` は撮影FPSメタデータとPTSが一致したときだけ。
- 品質ゲートの閾値（接地時間25%、ピッチ10%、短距離ピッチ下限2.0歩/秒）は暫定。DEC-016で実測から決める。
- 技術スタック: Python標準ライブラリのみ（numpy等がない環境で、依存を増やさない）。プレイヤーは素のHTML/JS（外部スクリプトなし）。
- 公開範囲: private（既定）。

## 02 Failure First
K1〜K27（state.json）。重視したのは「誤った精密値を出す」方向の失敗：固定FPS換算、PTS欠落時のFPS仮定、スロー書き出しを実時間として扱う、申告FPSを証明に使う、30fpsで接地時間を精密値扱い、区間が真値を含まない、生成フレームの混入、骨格の近傍フレームへのずれ、再生倍率の混入、訂正後の古い値。
検証は合成データ（真値が分かる走動作モデル）で、240/120/60/30fps・VFR・欠落・遮蔽・ブラー・スロー書き出しを作り、区間が真値を含むことを直接確かめる。

## 03 設計・実装
- 時刻は `Fraction`（整数PTS×分数time_base）で持ち、浮動小数で累積しない。
- イベント = 旧状態を最後に観測したフレームと新状態を最初に観測したフレームの区間。遮蔽・重複PTSフレームは「観測なし」として区間を広げ、要確認にする。
- 接地時間の範囲 = [離地.下限 − 接地.上限, 離地.上限 − 接地.下限]。範囲幅/値が許容を超えれば要確認。FPS一律の閾値は使わない。
- `analyze()` は再生倍率を引数に持たない。入力の索引は変更しない（コピーして処理）。
- スナップショットは版情報込みの正準JSONのSHA-256を `analysis_id` にする。
- プレイヤーは原本フレームの提示順インデックスで位置を持ち、`<video>.currentTime` を使わない。次フレームまでの待ち時間はPTS差÷倍率。
- 種目の妥当性チェック: 動画時間上のピッチが短距離として不自然に低ければスロー書き出しを疑い、秒指標を止める（メタデータのないスロー書き出し対策）。
