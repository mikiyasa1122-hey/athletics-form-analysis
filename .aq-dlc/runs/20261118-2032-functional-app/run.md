## 01 要求と成功条件
「アプリとして機能するレベルまで仕上げたい」。

### 人間への確認
- アプリの形 → ローカル1人用（ブラウザで使う。動画はPCの外に出さない）
- 姿勢推定 → RTMPose（rtmlib）。「ライセンスは課金か」と質問があり、回答した（コードは Apache 2.0 で無料、重みの学習データに研究・非商用限定のものが含まれうる。法的助言ではない）
- 種目 → 要件書の全種目
- 人物動画での検証 → 公開動画を探してよい → 「100 m female Athletissima 2012.ogv」（Wikimedia Commons、CC BY 3.0、Fanny、10.2MB）のダウンロードを確認後に取得
- 誤り: 確認の前に `pip download` で mediapipe・onnxruntime の wheel（計約43MB）を一時フォルダに保存してしまった。インストール・実行はしておらず、すぐ削除して報告した

### 仮定
- PC全体の Python は汚さず、`.venv` に rtmlib・onnxruntime（CPU版）を入れる。GPU（RTX 2070）用の onnxruntime-gpu は CUDA の準備が要るので今回は使わない
- 既定は精度優先（YOLOX-x + RTMPose-x 384x288）。balanced はプレビュー扱いで valid を出さない（ARCH-014）
- 解析対象は1人（最初に最も大きく映った人、以降は近い人）。人物選択の UI は後回し
- 地面の線は足の最下点から自動推定し、画面で上書きできる
- 改善提案は、承認済みの評価ルールがないので出さない（FR-FB-001, §8.3）
- サーバーは標準ライブラリ（ThreadingHTTPServer + SQLite）。127.0.0.1 のみ

## 02 Failure First
- 他サイトのページからローカルサーバーへの書き込み・削除（CSRF、DNSリバインディング）→ Host・Origin・JSON/専用ヘッダー必須、CORS 不許可（S-0001）
- パストラバーサル（ID・フレーム番号）、動画でないファイルのアップロード、失敗時の残骸
- 復号した画像と原本フレームIDのずれ（ffmpeg と ffprobe の枚数が違う）→ 枚数が一致しなければ止める
- 隣のレーンの選手への乗り移り、Halpe26 の点の対応の誤り
- 地面の推定の失敗（人物がいない・カメラが動く）で誤った接地を出す／解析全体が失敗する
- 未検証の種目で精密値を出す、投擲で走動作の指標を出す
- 二重実行・取り消せないジョブ・アプリ終了で残る孤児ジョブ
- 訂正で自動検出が消える、不正な訂正が残る

## 03 設計・実装
- `athform/disciplines.py`: 全種目と、種目×指標の公開状態（対応・試験的・手動確認・要校正・未対応）と、スロー検出の妥当範囲
- `athform/realpose.py`: ffmpeg で全フレームを BMP として提示順に取り出す（ヘッダーのサイズで確実に区切る）、RTMPose、追跡、地面の推定
- `athform/store.py` / `jobs.py` / `server.py` / `compare.py`
- `web/`: 一覧・アップロード、解析画面（実際の映像＋骨格＋地面の線、訂正、地面の指定、情報の編集、履歴、書き出し、削除）、比較
- 実装中に見つかって直したこと:
  - CSS の `display` が HTML の `hidden` を上書きし、画面が重なって表示された → `[hidden]{display:none!important}`
  - 人物を検出できないフレームでも骨格の記録（点はすべて空）があり、「骨格のフレームID 0」と表示された → 点が1つもなければ「なし」
  - 人物のいない動画で、地面を推定できずにジョブ全体が失敗した → 解析は保存し、理由を表示
  - 他サイトからの書き込みで、存在しないIDでは 403 より先に 404 が返り、IDの有無が分かった → Origin を最初に確認
  - 地面の傾きを求める条件が厳しすぎ（体の高さの2倍の移動）、普通の側面映像で水平とみなしていた → 1倍に。すると遊脚だけの区間の点に引っ張られて傾きが付き、誤った接地を検出した → 線から接地幅以上浮いた点を除いて当て直す。テストを左右端まで確かめる形に強化
  - Windows のシェルで UTF-8 の応答を cp932 で読んで失敗（F-0003/F-0004 と同じ）→ 確認スクリプトは Python で UTF-8 を明示

## 04 Quality Gate / レビュー
- gate 1回目: 全check PASS（python 125件）。
- 実映像（Athletissima 2012 女子100m、480フレーム、25fps、パンする中継映像）を精度優先で解析（CPUで約12分）。地面の推定は接地点2つ・傾き上限・イベント2つ。膝角度・体幹前傾が valid で出ていた。
- 独立レビュー1回目: fix_required（blocking 5 / non-blocking 10）
  - B1 保存済みの訂正が、地面の変更後の再解析を恒久的に失敗させる
  - B2 解析中の削除で残骸
  - B3 再解析でスナップショットを上書き
  - B4 追跡の乗り移りに印がない
  - B5 自動推定の地面の質が指標に反映されない（実映像で確認）
- 独立レビュー2回目: 途中で利用上限に当たって停止。利用者の指示で、新しいレビュー担当に引き継いで再開した。
  - 結果は fix_required（blocking 2）。B1〜B3 は解消。
  - 新 B1: 地面の前半と後半のずれの計算で傾きを差し引いておらず、少し傾いた固定カメラでも「カメラが動いている」と誤判定する。
  - 新 B2: 範囲内のすり替わりに印がない。取り直しの印は時間の区切りと重なり、結果に効いていない。
  - N1〜N10: 版と DB の食い違い、未適用の訂正が指標に出ない、旧形式データの移行、終わらない取消、など。
- 独立レビュー3回目: pass（blocking 0 / non-blocking 7）。
  - 前回の B1・B2 は解消。少し傾いた固定カメラ（0〜0.04、30〜120fps、体の高さ150〜450px）で誤検出なし。
  - 区切りが増えても値が出なくなることはない（240fps・見失い1%で接地時間 13→10）。
  - 実映像では、本当に2人が範囲内にいる場面で ambiguous が働いていた。
  - N1（取り直しフレームで足が見えないと区切りが落ちる）・N2（ambiguous が慎重すぎ）・N6（警告の見出し）に対応。
  - N3（重なりでの乗り移り）・N4（自動で閉じたジョブと削除）・N5（移行した旧版の状態）は README に限界として記載。
- 最終 gate: 全check PASS（python 145件、node 13件、real-ffprobe 19本）。

## 05 修正ループ
- fix_iterations=1（レビュー1回目）:
  - B1 → 当てられない訂正は「未適用」として版に記録し、取り消しは記録を残す。追加直後は厳密に確かめる。根本原因: 利用者の訂正を、再計算で変わる派生物の ID に結び付けた（F-0015）。
  - B2 → 解析中の削除は 409。ジョブは消えた動画のフォルダを作り直さない。画像は一時フォルダから入れ替える。
  - B3 → 版ごとのファイルを排他作成する。根本原因: 内容ハッシュを版のキーにした（F-0015）。
  - B4 → 範囲を広げない・大きさの連続性・取り直しの印で区切る。
  - B5 → 地面の質の問題を返し、自動推定なら最高 estimated、問題があれば review_required にする。実映像の再計算で4つの問題を検出し、valid は出なくなった。
  - N1〜N10 にも対応。データの置き場所を ~/.athform/data に移した（F-0017: プロジェクト内のデータで gate が古い扱いになる）。
- fix_iterations=2（レビュー2回目）:
  - 新 B1 → 傾きを差し引いた高さで比べる。固定カメラの傾き 0.02/0.05 では問題なし、パンでは問題ありをテストにした。最初のテスト素材は「時間と横位置が一緒に動く」ため傾きと区別できなかったので、パン（選手がほぼ同じ x）を表す素材に直した。
  - 新 B2 → 範囲を最後に見てからの時間に比例させる（8 体長/秒、0.15〜0.6）。1フレームでも見失った後の回復には印を付け、2人以上いれば決めない。根本原因: 「見失った長さ」だけで取り直しを判定し、範囲内のすり替わりを考えていなかった。
  - N1・N2・N3（移行）・N4〜N7・N10 に対応。N8（25〜30fps での区切り）は物理的に正しい振る舞いとして README に書いた。
